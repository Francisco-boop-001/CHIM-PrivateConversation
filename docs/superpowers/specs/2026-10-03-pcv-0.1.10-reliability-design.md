# Private Conversation 0.1.10 — reliability design

Date: 2026-10-03. Status: approved by the user in conversation; awaiting written-spec review.
Evidence: `tasks/live-issues-2026-10-03.md` (first in-game session of 0.1.9, read-only inspection of
the live server). Group mode and free mode are out of scope (`tasks/feature-requests.md`); they
follow in 0.1.11/0.1.12 with their own design.

## Goals

Make published scene behaviour hold up in real play:

- A pair scene survives a partner briefly leaving the close range.
- The Logs page works from the player's normal browser link.
- A solo reflection is thinking aloud, not talking to someone.
- A silent turn is explainable, and early-line ACKs no longer read as failures.

Fail-closed behaviour for **starting** a scene is unchanged.

## 1. Presence during an active scene (live issue 4) — decision: grace period plus wider range

Today every request inside an active scene re-checks that each participant is in the close
`infonpc_close` report. If one is missing at that instant, the scene is blocked for that request
(`state.scope_skipped` / `routing.request_skipped` `scene_not_eligible`). Live evidence:

- 09:45:29Z and 10:06:41Z: rechats refused (Bruce out of range; the first report after a ~4-min gap
  was only a baseline).
- 10:01:27Z: rechat accepted once Bruce was back in range.

New rule, applied only to requests for an **already active** scene:

- A participant absent from the close report still counts as present if **either**:
  1. **Grace:** they were present in a close report within the last **60 s** (`PCV_PRESENCE_ACTIVE_GRACE = 60`), measured with the existing server clock and same-second tolerance; **or**
  2. **Wider range:** they appear, uniquely by catalog name, in the most recent fresh wider
     `infonpc` report ("beings in range"), captured and validated like the close report (freshness
     TTL, crowd bound 128, duplicate names ambiguous).
- The first close report after a gap longer than the freshness window (today a `presence_baseline`)
  does not invalidate the grace check for participants seen within 60 s.
- If neither holds for any participant, the request is refused as today, and the log entry adds
  `missing_actor_ids` and `presence_check` (`close`, `grace_expired`, `wide_absent`,
  `wide_unavailable`).
- Activation (pending → active) still requires every participant in a fresh close report.
- Pre-implementation check: confirm on the clone that CHIM passes the `infonpc` event to plugin
  hooks the way it passes `infonpc_close`. If it does not, ship the grace rule only and record this
  in the release notes.

Not relied on: the client's tendency to bring a listener back to the speaker. It was observed by the
user in game and is consistent with one log sample (Bruce back in range at 10:00:08Z before his
10:01:27Z turn), but it is not in server code and is not verified.

## 2. Logs page access from the host browser (live issue 2) — decision: trust the WSL host only

Today `pcv_ui_logs_access_allowed` admits only `REMOTE_ADDR` 127.0.0.1/::1 (without forwarding
headers) or an authenticated `REMOTE_USER`. The player's browser uses
`http://172.17.226.57:8081/...` (the WSL VM address), so `REMOTE_ADDR` is the Windows host on the
virtual switch, and the request is refused (`ui.diagnostics_rejected access_denied`, 09:28:48Z).

- Also admit exactly one address: the IPv4 default gateway of the server, read from `/proc/net/route`
  (the Windows host in WSL2 NAT mode).
- Admit it only when it is a private address. Forwarding headers still disqualify the request.
  Unreadable or ambiguous routing data admits nothing extra.
- A refused request renders an explanation with a link to the `127.0.0.1:8081` URL of the same
  page, instead of a bare refusal.
- Out of scope: any broader private-range trust.

## 3. Solo reflection is thinking aloud (live issue 5) — decision: strictly to oneself

Live solo lines addressed the subject who stood nearby ("Bruce. You. You're s'till here.").

- Replace the solo guidance in `server/scope.php` with: think aloud, addressed to no one; do not
  address anyone present, including the person being thought about; refer to them in the third
  person. Keep the existing brevity sentence.
- Verify on the clone with the subject in the audience snapshot. Report the compliance rate; it is
  model-dependent.

## 4. Explainable silent turns (live issue 1)

`routing.request_finished` `request_unobserved` currently covers both failures and CHIM's
deliberate stops (10:14:26Z: `Rechat: pre-roll budget exhausted (2/2) — terminating`).

- Add to the unobserved finish entry: `request_type` (`inputtext`, `rechat`, …), `elapsed_ms`, and
  the actor IDs in scope.
- If CHIM exposes the rechat-budget termination to plugin hooks (to be checked in CHIM source on
  the clone), log reason `chain_ended_by_chim` instead. Otherwise document that a silent rechat
  after the budget is expected.
- Plugin page status gains one line, "Last scene turn: spoke / ended without speech (time)", read
  from PCV's own state. Never dialogue text.
- The 09:27Z `inputtext` silence remains open. On the next occurrence, read CHIM's log and
  `[LLM_RANDOMIZER]` lines immediately (read-only).

## 5. Early-line ACKs (live issue 3)

The real client ACKs lines while CHIM is still generating, so ACKs arrive before registration and
log `reflection.ack_skipped registration_missing` (09:35:09Z, 09:42:07Z).

- When an ACK matches the active solo scope and actor, and a solo request for that scope started
  within the last 180 s and has not finished, log `reflection.ack_pending` (debug severity, reason
  `reply_in_progress`) instead.
- All other `registration_missing` cases are unchanged.
- The existing early-ACK receipt path is unchanged; the final-line ACK still drives evaluation.

## 6. Testing and release

- **Failing test first** for each of: grace and wide-range rules (including the baseline-after-gap
  case and grace expiry), host-gateway access (allowed host, other private address, forwarded
  headers, unreadable routes), solo guidance text, unobserved finish context, and the
  `reply_in_progress` classification.
- **Simulator:** `scripts/live-test/` learns three real-client behaviours:
  - ACK lines before the response completes;
  - drop a participant from heartbeats mid-scene, then restore them;
  - pause heartbeats beyond the freshness window, then resume.
- **Clone run:** a focused live run on `DwemerAI4Skyrim3-test` (budget about 30 AI calls) covering
  sections 1, 3, 4 and 5. The gaming server must be stopped while the clone runs (shared WSL2
  networking).
- **Release gate:**
  - the full offline suite passes;
  - the clone run passes;
  - the user's in-game check;
  - then build from the final commit, tag `private_conversation-v0.1.10`, create the GitHub
    release, and push `main` (in that order).
  - The hub (CHIM-Plugins) and its pinned copy are updated by the Mind Poisoning agent.

## Non-goals

Group mode, free mode, A/B ordering changes (live issue 6), and any change to Mind Poisoning.
