# Private Conversation 0.1.13: reliability fixes

**Date:** 2026-10-03.
**Source:** rechecked audit findings in `tasks/audit-2026-10-03.md`.
**User decision:** "we do the fixes, when done? we begin the improvements." The defaults below were chosen by the lead and are reported to the user with the result.

## E1: no silent switch-off mid-scene

- **Sliding TTL.** Each request that keeps the scene active renews `expires_at = now + PCV_ACTIVE_TTL`, at most once per minute. The renewal time is stored as `renewed_at`, and validation accepts `expires_at <= max(activated_at, renewed_at) + TTL`.
- **Effect.** A scene now ends after 60 minutes **without a scene turn**, not 60 minutes after it started.
- **Expiry handling** is unchanged: it is logged and the scene turns off. The README says so plainly ("ends after an hour without use").
- **Rejected alternative:** blocking the first input after expiry. Expiry is only detected lazily, at the next request, which may come hours later. Blocking the player's first ordinary line after a long break would be worse than the narrow risk it removes.

## E2: END recovers an unreadable state file

- When `pcv_stage` receives END (a disabled config) and the store is unavailable because of `invalid_json`, `invalid_state` or `state_too_large`:
  - it renames the bad file to `state.json.corrupt-<unix>-<rand>`, preserving the evidence;
  - writes an empty store;
  - logs the new event `state.store_recovered` (warning, outcome `recovered`, reason = the load reason).
- **ARM** on a corrupt store still fails closed and never overwrites it (existing test).
- Symlinks, non-regular files and stat/read failures are not "recovered": they may indicate tampering or an IO fault.

## E3: an identity hiccup only blocks when a scene exists

- `pcvScopeStoredStateExists` returns true only when the file:
  - exists and is unreadable, corrupt or unsafe (fail closed, as today); or
  - parses and holds a non-null `active` or `pending` slot.
- A readable store with both slots null returns false.

## E4: presence read errors are logged and never cause drops

- The in-scene and wide presence reads log a caught Throwable as `state.unavailable` / `presence_unavailable` (operation `presence_read`) and report `error: true`.
- **Error turns block, never drop.** `pcv_begin_request` gains `bool $allowActiveDrops = true`. When the in-scene evidence had an error, routing passes false, and a narrowing that would drop members becomes a refusal for that turn (`scene_not_eligible`, presence_check `presence_error`).

## E5: stuck scenes end themselves

- **Auto-end.** When an active scene is refused (`blockedActive`), its state records `refused_since` (first refusal time). A later refusal at least **300 s** after `refused_since` ends the scene:
  - active is cleared;
  - `state.scope_ended` is logged with reason `members_gone`;
  - the page shows "The scene ended: its NPCs were gone for five minutes."
- Any accepted turn clears `refused_since`.
- **Queued scene not nearby** (pending blocked while a scene is active): the behaviour is kept (fail closed), but the refusal message names the queued scene: "The queued scene's NPCs are not nearby; your input was not sent. Press END or ARM again."

## E6: solo reflection uses the same presence rule as routing, except during heartbeat gaps

- `pcvReadResolvedScope` for an **active** scene adds the in-scene map (grace and wide) to the strict map, **only when the close report is fresh** (`report_fresh`). A heartbeat gap keeps the strict rule, so simulator case 8c still rejects.

## E7: drop the dead presence.json write

- The ordinary-input presence snapshot is still parsed for routing, but no longer written to `presence.json`. Invalidation keeps deleting an old file.
- The registry-first ACK reordering is **not** done: early ACKs arrive before registration (0.1.7 recovery), so skipping unregistered lines would break that recovery.

## E9: honest logs

- **(a)** A refused direction (`scene_not_eligible`) is logged as `routing.request_blocked` (warning, blocked) instead of info-level skipped.
- **(b)** The reflection scope read reports the new reason `scope_unavailable` when it failed with an error, distinct from `identity_changed`. The exception is logged as `state.unavailable`.
- **(c)** A new test collects every literal `pcv_log_event(...)` call in `server/` and checks it against the rules, so a typo can no longer silently drop events.

## Out of scope

- E8 (lock timeout).
- E10 items, except where a fix above touches them.
- Gameplay improvements (they come after this release).

## Testing and release

- A failing test first for each item.
- Full offline suite.
- One small clone smoke run (about 10 AI calls; cases 2, 5a, 17 and 20) to check for regressions.
- Ask the user before publishing v0.1.13.

## Implementation notes (2026-10-03)

- **E5 queued-scene message:** dropped. The refusal body goes to the game client, not to the player, so changing its wording would not reach anyone. The page already shows the queued scene.
- **E7 dead write:** deferred. `tests/eligibility_check.php` deliberately tests the cached `presence.json` (wrong playthrough, redaction), and removing a write of about 1 ms would mean rewriting those safety tests. Revisit only alongside a cache redesign.
- **E9b in practice:** `pcvReadResolvedScope` catches catalog errors itself and logs them, so those surface as `scope_changed` after a `state.unavailable` line. `scope_unavailable` covers identity and other failures that escape it.
