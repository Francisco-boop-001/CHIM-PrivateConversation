# Private Conversation 0.1.11 — group mode design

Date: 2026-10-03. Status: approved by the user in conversation; awaiting written-spec review.
Origin: community request (DemodiX [CHIM]: NPC checklist instead of A/B; three-person scenes) in
`tasks/feature-requests.md`, plus live issue 6 (A always opens) in `tasks/live-issues-2026-10-03.md`.
Free mode is the next release; overheard-gossip judging belongs to Mind Poisoning (request handed to its agent).

## Decisions (user)

| Topic | Decision |
| --- | --- |
| Who speaks after the opener | CHIM's rechat chooses; PCV keeps it inside the scene's members |
| Group size | 2–4 NPCs; pair mode becomes a 2-member group |
| Gossip effects | Overhearers should be judged too; Mind Poisoning implements it, while PCV guarantees the witness list is exactly the members and ships without waiting |
| Opener | Auto: the earliest-named member in the direction, else the opener picker, else the first checked |
| Missing members at start | Start with those present if at least 2; the missing are dropped for this scene and do not join later |
| Member gone during the scene (designer's choice, approved) | After the 0.1.10 grace/wide checks fail, drop that member and continue if 2 remain; otherwise refuse as today |

## 1. Configuration and compatibility

- Stored config for non-solo scenes:
  - the internal `scene_mode` stays `'pair'` (now 2–4 members); the UI calls it Group;
  - `actor_a`/`actor_b` mirror the first two members, so existing solo, reflection and logging code and old
    logs stay valid;
  - `actor_ids`: 2–4 distinct catalog ID strings in checklist order (`actor_ids[0] === actor_a`,
    `actor_ids[1] === actor_b`);
  - `opener`: `'auto'` or one of `actor_ids`;
  - `exclude_player`, `bystander_mode` as today.
- Stored `pair` configs (`actor_a`, `actor_b`) remain readable. On read they map to a group with
  `actor_ids = [actor_a, actor_b]` and `opener = actor_a` (today's behaviour), so an active or pending pair
  survives the upgrade. New stages always write `group`.
- Active state gains `members`: the participant IDs fixed at activation (a subset of `actor_ids`) and
  `dropped`: IDs left out, with a reason (`not_eligible_at_start`, `left_scene`).
- Solo config and behaviour are unchanged.
- State validation bounds:
  - at most 4 IDs, no duplicates, at least 2 members while active;
  - a valid ID is `/^[1-9][0-9]*$/` and must be in the catalog at stage time.

## 2. Page

- Non-solo selection becomes a checklist of eligible NPCs, at most 4 checked (enforced server-side).
- An "Opener" select: `Auto` (default) or one of the checked NPCs.
- The status panel lists the members, the dropped NPCs with their reason, and the existing last-scene-turn line.
- ARM requires at least 2 checked; END and Solo are unchanged.

## 3. Activation

On the next eligible ordinary input with a pending group:

- **Members** are the checked IDs that are strictly eligible (close report and fresh activity, exactly as
  today's activation check).
- With at least 2 members the scene activates. The others are recorded as `dropped`
  (`not_eligible_at_start`) and logged.
- With fewer than 2 members the pending scene stays pending (`scene_not_eligible`), as pairs do today.
- Dropped NPCs never rejoin the active scene.

## 4. Opener selection

For each ordinary input that starts a scene turn (not a rechat):

1. Take the direction text (the player input after PCV's prefix handling).
2. Find the earliest occurrence of any member's name. A member matches by its full catalog name, or by its
   first word when that first word is unique among the members (case-insensitive, word-boundary). The earliest
   position wins; ties go to the longer match.
3. If no member is named:
   - use `opener` when it is a member;
   - otherwise use the first member in checklist order.
4. Log `opener_source`: `named`, `picker` or `first`.

A named member is the speaker for that turn, which resolves live issue 6 ("What does Bruce reply?" → Bruce).

## 5. Speaking turns and routing

- Audience, `CACHE_PEOPLE`/`CACHE_PEOPLE_LIMITED` and the routing snapshot contain exactly the members, plus
  the player when included. `present_actors` is cleared as today.
- Rechat payload `active_agents` are clamped to the members. The rechat speaker must be a member; anything
  else is blocked as today (`rechat_speaker_outside_pair` becomes `rechat_speaker_outside_scene`; the old
  reason stays accepted by the log reader).
- Generated speakers are checked against the member set (`speaker_outside_pair` becomes
  `speaker_outside_scene`).
- Scene guidance:
  - for two members it keeps today's wording;
  - for three or four it names all members, says only they may speak, and that each should respond to
    whoever spoke last or whoever is addressed.
- **Verified on the clone:** PCV forces CHIM's `tight` rechat mode (`context_pre.php`). In that mode the
  listener named by a generated line answers next, within `active_agents`. The listener enum therefore
  becomes every member except the speaker, and the model chooses whom it addresses. No PCV-side rechat
  targeting is needed.

## 6. During the scene

- The 0.1.10 in-scene presence rules (named in the current close report, 60 s grace, wide report) apply to
  every member.
- A member failing all checks is dropped (`left_scene`) when at least 2 others still pass. The turn proceeds
  with the remaining members, and the drop is logged and shown.
- If fewer than 2 would remain, the request is refused as today (`scene_not_eligible`, with
  `presence_check` and `missing_count`).

## 7. Mind Poisoning

- No API change is needed for group mode. Each line's `eventlog.people` witness list contains exactly the
  members (plus the player if included); verify this in the clone run.
- The addressed listener is judged as today. Overhearer judging arrives when Mind Poisoning implements the
  requested multi-listener evaluation; PCV documents it then.
- Solo reflection registration is unchanged.

## 8. Logs

- New context keys:
  - `member_count`, `dropped_count` (integers);
  - `opener_source` (`named`, `picker`, `first`);
  - `drop_reason` (`not_eligible_at_start`, `left_scene`).
- `scene_mode` stays `pair`/`solo`; `member_count` distinguishes groups.
- New reasons `rechat_speaker_outside_scene` and `speaker_outside_scene` are added; the old reasons stay
  valid for existing log lines.

## 9. Testing and release

- **Failing tests first** for each of:
  - config read compatibility (pair → group);
  - stage validation (2–4, unique, opener ∈ checked);
  - activation with partial presence (3 checked / 2 present → active with 1 dropped; 3 checked / 1 present →
    pending);
  - opener selection (full name, unique first name, ambiguous first name, earliest wins, picker, first);
  - rechat clamp and speaker checks for 3 members;
  - mid-scene drop (continue at 2; refuse below 2);
  - guidance text for 2 and for 3+;
  - log keys.
- **Simulator:** 3-member group cases with Lidia, Aela and Bruce:
  - named opener;
  - CHIM-chosen rechats;
  - a member leaving beyond grace and wide;
  - a member missing at start.
- **Clone run:** about 30 AI calls, gaming distro stopped.
- **Release:** full suite on the merged result, build, tag `private_conversation-v0.1.11`, GitHub release,
  push `main`, then the hub message for the Mind Poisoning agent.

## Non-goals

- Free mode.
- Latecomers joining a running scene.
- More than 4 members.
- Any Mind Poisoning change.
- Changing solo reflection.
