## Engineering findings
All rechecked in code by the lead on 2026-10-03. Severity is the rechecked one.

| ID | Sev | Finding | Recheck verdict |
|---|---|---|---|
| E1 | HIGH | Active scene expires 3600 s after activation (`PCV_ACTIVE_TTL`, never renewed). The next direction is routed as normal player speech (preprocessing.php:143). This contradicts README:125 "not quietly replayed". | Confirmed. Fix: renew the TTL on each routed turn; block or notify on the first input after expiry. |
| E2 | HIGH | Corrupt or invalid state.json: `pcv_load_store` (state.php:562-597) returns unavailable, so all input is blocked, and `pcv_stage` refuses, so END cannot recover. | Confirmed. Fix: END overwrites an unreadable store with an empty one and logs it. |
| E3 | MED-HIGH | After any use, state.json persists; any identity failure then blocks input via `pcvScopeStoredStateExists` (scope.php:403, preprocessing.php:82). | Confirmed. Fix: block only if the stored file holds an active or pending slot. |
| E4 | LOW-MED | Presence read errors are swallowed silently (state.php:1286, 1328). | Partly confirmed. A total read failure leads to refusal, not drops (fewer than 2 members remain), so the scene survives. A wrong drop only happens when the close report reads fine, the wide read throws, and a member is in the wide report only. The silent swallow (no log) is confirmed. Fix: log it; treat "evidence unavailable" as refuse, not drop. |
| E5 | MED | Stuck scenes: `blockedActive` never clears the active slot (refused up to 60 min until END). A pending re-ARM with ineligible NPCs blocks the running scene's input too. | Confirmed. The second part is partly intended: the typed direction was meant for the new scene, so blocking beats misrouting, but the refusal gives no reason. Fix: auto-end after N refusals or X minutes; clearer refusal message and page note. |
| E6 | MED | Reflection ACK path (`pcvReadResolvedScope`, scope.php:417-418) uses the strict fresh map; routing uses in-scene grace/wide. | Confirmed with nuance: the strictness on stale presence is intended (simulator case 8c). The gap is an NPC drifting slightly during a long reply, whose reflection is then silently discarded. Fix: use the in-scene map for an already-active solo scene, keep stale handling. |
| E7 | LOW-MED | Waste: `pcvScopeKnownNpcs` runs 3 times per input (scope.php:78, state.php:1308, scope.php:532); presence.json is written every input and read by nothing; the solo ACK path runs identity, catalog and presence work for every `_speech` (reflection.php:66) before the registered-line probe; directory safety walk on every log line. | Confirmed. CHIM PERF puts each `_speech` at 70-240 ms total. Fix: per-request caches, drop the dead write, probe the registry first. |
| E8 | LOW | `pcv_lock_state` uses blocking flock with no timeout (state.php:423). | Confirmed but theoretical: locks are held briefly on local files and released on process death. Fix later, if at all. |
| E9 | MED | Observability problems, all confirmed: (a) a refused direction (`scene_not_eligible`, HTTP 409) is logged as info "skipped" (scope.php:965-975); (b) any Throwable in the reflection check is logged as `identity_changed` (reflection.php:604, 728, 1197); (c) unknown event or reason codes are silently dropped (log.php:1060-1063). | Fix: warning/blocked with `presence_check`; a distinct `storage_error`; a test listing every literal reason. |
| E10 | LOW | Smaller items: (a) the `pcvScopeConfigActorIds` fallback returns [null,null] for a pending free scene (scope.php:232-243; only reachable without state.php); (b) the pending-END path is dead in current flow (`pcv_stage` clears immediately), kept only for old stored states; (c) solo in-flight marker is unlocked and cleared unconditionally (state.php ~1744-1788; affects classification only); (d) rechat JSON decoded twice. | All confirmed, low. |
| E11 | — | Test gaps for E1-E6, E9c and concurrency. | Write each test first. |
