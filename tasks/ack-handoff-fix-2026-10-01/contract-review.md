# Early-ACK contract review — 2026-10-01

## Ruling

The frozen PCV implementation preserves both request epochs for new version-2 registrations and requires `ack_generation == source_generation == fresh_current_generation` before evaluation, at MP `pre_model` revalidation and at transaction revalidation. A source-generation snapshot alone would be insufficient: API v1 reads the interaction token from the PHP request currently invoking it. During ACK-side evaluation that is the ACK token; during registration-side recovery it is the source token. The native speech row does not contain the ACK token.

Legacy version-1 registry records remain accepted on the historical **direct ACK** path for compatibility. They contain no saved source epoch, so their evaluation gets the current ACK-request gate and existing scope checks, but not the new source/ACK epoch equality guarantee. Recovered receipts require a version-2 record and are not usable with v1 registrations. This is a deliberate compatibility boundary, not proof that old records carry the new invariant.

No MP API implementation change is indicated. `mindPoisoningEvaluateReflection()` accepts a `_speech` request array and the integration contract requires a matching native ACK (`projects/CHIM-MindPoisoning/server/reflection.php`, `projects/CHIM-MindPoisoning/docs/integration-api.md:24`). The recovered call uses a bounded representation of fields read from the actual unique native row, not invented speech; PCV retains separate ACK admissibility metadata because the row omits the request generation. API-v1 recovered-receipt compatibility is established by the isolated actual-evaluator fixture, not by a new MP interface. This is source/fixture evidence, not runtime certification.

## Frozen implementation review

The ACK prerequest captures the ACK epoch and a bounded receipt before core inserts `public.speech` (`pcvReflectionEvaluateAck()` in `server/reflection.php`; `pcv_reflection_store_ack_receipt()` in `server/reflection_receipt.php`). The receipt contains utterance ID, PCV key/config/actor, ACK generation, server timestamp and tuple digest, not raw speech. A matching already-registered direct ACK goes through the existing API-v1 request path without occupying receipt capacity. Otherwise `pcvReflectionQueueAckReconciliation()` probes the exact row after core intake, while `pcv_reflection_register_with_store()` independently checks pending receipts. `pcv_reflection_read_native_ack()` uses a parameterized ID lookup with `LIMIT 2`, bounded fields, and rejects missing, duplicate, invalid or unavailable rows; `pcv_reflection_lookup_native_ack()` opens the fresh connection for it. The provider/effect path uses the existing claim and is not automatically retried.

Pending receipt capacity is eight entries and 8 KiB with a 45-second lookup lifetime; the single registration/claim record remains separately bounded to 600 seconds. Entries survive while fresh, and a ninth unmatched receipt is explicitly busy rather than evicting a candidate. A duplicate for a retained, unexpired ID reuses its original timestamp; after expiry the old entry is pruned and a later ACK request with the same ID is captured as a new request. The fixture verifies both behaviors. That is not an automatic provider retry, and a permanent same-ID replay tombstone is not implemented. A fresh unresolved registered/claimed effect can block another output registration until it is consumed or expires, even after END/rearm. END makes a later effect fail fresh state checks but does not revoke already committed/in-flight work or clear that unresolved record.

The native SQL fixture passed ten disposable-database cases (missing row; transaction visibility; exact ID and Unicode tuple; oversize text; identical/conflicting duplicates; duplicate plus oversized row; closed connection; missing table; isolated reader). The separate production-hook fixture passed four scenarios: matching ACK commits once after `INSERT` then `die()`, mismatched tuple does not invoke the evaluator, stale generation skips the post-intake query, and changed scope blocks evaluation. It executes copied production prerequest/queue/shutdown/registration/reader code against a disposable PostgreSQL cluster; the CHIM environment, `StoreDb`, evaluator and provider are stubs. These fixtures do not prove the installed CHIM schema/index, live callback environment, real provider or gameplay. The earlier captured stdout's `Private Conversation logger: invalid_event` warning (request ID `35e57533-7a30-439c-858c-b2cee0592af9`) came from the busy-registration fixture: `reflection.registration_skipped(info, skipped, registration_busy)` passed its event-specific validation, but the shared reason-code whitelist rejected `registration_busy`. The main owner added the missing reasons. The refreshed registry fixture now asserts busy, interaction-stale and corrupt-receipt events and no `invalid_event`; the focused logger check and four-test package check also pass. The old raw stdout is pre-fix evidence.

## Required epoch contract

1. In the original generation request, capture the immutable source request token before any later hook or core SQL can change the relationship between request and shared state; retain it in the registration. Do not infer the source token from the value at `prepostrequest` if no request-start snapshot was established.
2. At ACK prerequest, before core inserts `public.speech`, call the existing interaction gate and retain its captured integer only when the ACK request is currently enabled and admissible. `chimInteractionBegin()` uses the supplied header when present and the current shared generation when absent; preserve that absent-header fallback exactly. Store receipt ID, private PCV key/config/actor binding, ACK generation, trusted server receipt time, and a digest binding the normalized tuple. Store no raw dialogue.
3. A recovered receipt is eligible only when `ack_generation == source_generation == fresh_current_generation` and the current state is enabled. Check that condition when reconciling, at **every** `pre_model` revalidation, and at **transaction** revalidation. In the source request, v1's own gate only covers `source_generation`; the PCV callback explicitly covers `ack_generation`. In the ACK request, v1's gate covers `ack_generation`; the callback also covers the saved source epoch. Compare captured values; never rewrite request globals. This new equality guarantee is for v2 registrations/recovery; accepted legacy v1 direct records lack a source token.
4. If the ACK header is absent, the retained epoch is the value captured by CHIM's request-start fallback—not a later shared-state read. A stale or malformed explicit header cannot be repaired from a valid current source epoch or a persisted dialogue row.

The critical negative fixture is: source token/current state are G5, but ACK starts with explicit stale header G4. Core can insert the native row before its later interaction exit. Registration-side v1 sees G5 and would otherwise accept it. The captured ACK gate must make this fail before provider work. Also test an Off/On transition after receipt capture; both epochs then mismatch fresh state even if the row and registration remain present.

The per-ID receipt map is justified by CHIM output chunking: the lead's pinned-source inspection found `returnLines()` emits each sentence (`lib/chat_helper_functions.php:1355`), while each emitted line receives a fresh `SCRIPTLINE_UTTERANCE_ID` and the global ends with the last emitted ID (`lib/chat_helper_functions.php:2014, 2046`). An earlier sentence receipt may therefore arrive before PCV registers the final sentence. It must not occupy a single unknown-receipt slot that prevents capturing the final ID. A final-ID registration/ACK must match its own entry while unrelated earlier receipts remain pending; capacity remains deliberately bounded, not lossless for more than eight retained candidates.

## Diagnostic and proof limits

`pcvRoutingLogStart()` emits `routing.request_started` for routed requests, and `pcv_log_event()` registers the terminal shutdown observer for that event. The `_speech` prerequest branch returns before `pcvRoutingLogStart()`, so an ACK request does not guarantee that observer is present. If it was registered earlier, its shutdown callback runs before the later ACK-reconciliation callback. The logger permits later event appends, so a separate reflection result can still be recorded. Keep `routing.request_finished` routing-only; it does not certify an opinion outcome.

Confirmed by source and isolated fixtures: MP v1's per-request gate checks the current request's captured global, with pre-model and transaction gates still active. PCV v2 registration/recovery retains both epochs, exact ACK digest/native-row checks and scope revalidation; legacy v1 direct records remain a documented compatibility exception. The registry fixture covers both arrival orders, stale ACK generation, pre-model/transaction changes, receipt capacity/expiry, post-expiry recapture and once-only claims; the database fixture covers ten SQL-reader cases and four production-hook callback scenarios. The logger warning was a fixture reason-whitelist failure and the refreshed registry, logger and package checks pass. Still unverified: native-row visibility at every shutdown boundary in full CHIM intake, installed schema/index state, and actual client generation-header behavior in every transport. These fixtures do not establish gameplay or absolute replay impossibility; process crashes before registration/callback and explicit capacity busy remain liveness limits.
